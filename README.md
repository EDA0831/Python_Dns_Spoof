# ARP + DNS Spoofing (MITM) Tester

ARP 스푸핑으로 피해자와 게이트웨이 사이에 끼어든 뒤(MITM), 피해자의 DNS 질의를 가로채
**진짜 응답보다 먼저** 위조 응답을 보내 원하는 IP로 유도하는 Python 학습용 도구. (Linux / Windows 공용)

> ⚠️ **본인 소유이거나 명시적으로 허가받은 '격리된 랩 네트워크'(host-only/internal)에서만 사용해야 합니다.**
> 같은 네트워크의 타인 트래픽을 가로채는 행위는 정보통신망법·통신비밀보호법 등 관련 법률 위반이며,
> 그로 인한 책임은 사용자 본인에게 있습니다. 이 프로젝트는 보안 학습 및 방어 검증 목적으로만 제공됩니다.

---

## 주요 기능

- ARP 스푸핑으로 **피해자 ↔ 게이트웨이 양방향 MITM** (주기적 재감염으로 위치 유지)
- 피해자 DNS 질의(UDP 53) 스니핑 → 지정 도메인이면 **위조 응답을 레이스로 선점**
- `도메인 → 가짜 IP` 매핑 지정 (부분 일치)
- **IP 포워딩 자동 토글** — Linux `/proc`, Windows PowerShell(`Set-NetIPInterface`) → MITM 중에도 나머지 트래픽 정상 흐름
- 종료 시 **ARP 캐시 자동 복구** (피해자 네트워크 원복)
- 인터페이스 **번호 선택 메뉴**, 가짜 서버 IP는 피싱 서버가 이 머신이면 **자동 기본값**

## 요구 사항

- Python 3.x, `scapy` (`pip install scapy`)
- **Linux**: root 권한
- **Windows**: 관리자 권한 + **Npcap**(설치 시 'WinPcap API-compatible Mode' 체크)
  - scapy가 Npcap으로 L2 프레임을 직접 주입하므로 윈도우 raw 소켓 제한을 우회한다.

## 사용법

```bash
python Dns_Spoof.py        # Linux는 sudo, Windows는 관리자 권한
```

실행하면 대화형으로 입력받는다.

```
인터페이스 번호 선택: 1            # 피해자와 같은 서브넷의 어댑터
피해자(타겟) IP: 192.168.6.20
게이트웨이 IP: 192.168.6.1
스푸핑할 도메인 (예: naver.com): test.local
가짜 서버 IP (리다이렉트 대상) [엔터=이 머신 192.168.6.1]:
```

- 중단: `Ctrl+C` → ARP 캐시 자동 복구 후 종료
- 상단 `ARP_INTERVAL`, `VERBOSE_QUERIES` 등으로 동작 조정

## 동작 원리

1. `get_mac`으로 피해자·게이트웨이의 MAC을 확보한다.
2. IP 포워딩을 켠다 — 피해자의 나머지 트래픽을 정상 전달해 공격을 눈치채지 못하게 한다.
3. 양쪽에 위조 ARP(`is-at`)를 주기적으로 보내 **서로의 IP가 공격자 MAC에 있다고** 속인다(MITM).
4. 이제 피해자의 DNS 질의가 공격자를 거치므로 `sniff`로 포착한다.
5. 질의가 지정 도메인이면, **트랜잭션 ID·질문부·포트를 그대로 되비춘 위조 응답**을 진짜 응답보다 먼저 보낸다.
6. 종료 시 올바른 MAC으로 ARP 캐시를 복구한다.

## 방어 관점 (같이 보면 좋음)

이 공격이 **왜 현실에서 점점 안 통하는지**가 곧 방어 포인트다.

- **DNSSEC** — 응답에 서명을 붙여 위조를 탐지.
- **정적 ARP / Dynamic ARP Inspection(DAI)·DHCP 스누핑** — ARP 스푸핑 자체를 차단(스위치 레벨).
- **DoH / DoT** — DNS를 HTTPS/TLS로 암호화 → 평문 UDP 53 위조가 무력화됨. (요즘 브라우저 기본값이라 실제로 이 공격이 브라우저엔 잘 안 먹는 핵심 이유)
- **HTTPS + HSTS** — DNS가 바뀌어도 인증서 불일치·https 강제로 가짜 서버 접속을 막음.

## 한계

- **같은 L2 세그먼트(브로드캐스트 도메인)** 안에서만 동작 — 라우터 너머의 대상은 불가.
- 피해자 브라우저가 **DoH**를 쓰면 평문 DNS 위조가 통하지 않는다(`nslookup`엔 걸려도 브라우저엔 안 걸림).
- **HTTPS/HSTS** 사이트는 DNS를 바꿔도 브라우저가 차단한다.
- 진짜 DNS 응답과의 **레이스** — 환경에 따라 선점에 실패할 수 있다.
